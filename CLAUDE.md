# Eigen — math for ML, learned by playing

Next.js 16 (App Router) + Prisma 6.19 + Neon Postgres. Invite-only student accounts, one teacher.

## How it fits together

- `lib/content/` — the course. Concepts are TS objects in a dependency graph (`deps`). Each concept is taught by fixed steps: motivate → explore (widget) → truth → connect → check → predict (misconception dislodge) → ml → produce. Answers live here and **never reach the browser**: `publicSteps`/`publicItem` strip them.
- `lib/check/` — answer checking. Expressions are compared by evaluating at many random bindings (method studied from Khan Academy Perseus, MIT; spec in `../reverse engineer/docs/spec/perseus-answer-checking.md`). Numbers, vectors, matrices cellwise. `traps` / wrong `forms` catch specific misconceptions.
- `lib/learning/rules.ts` — the learning system's rules (ported from `Desktop/learning/.claude/skills/teach`) as pure functions. UNKNOWN → EDGE → LANDED → SOLID; MISCONCEPTION must be dislodged. Only unaided production makes SOLID. Spaced review 1,2,4…90 days; a miss resets to 1 day and drops to EDGE.
- `lib/learning/progress.ts` — the only write path for progress: grade → append Attempt → apply rule → XP/streak, in one transaction.
- `components/widgets/Widgets.tsx` — interactive SVG plane: vector, vector-add, scale, combo, transform (draggable î/ĵ, optional area/determinant), compose, solve (drag x until Ax hits b).
- `lib/tutor.ts` — AI hint tutor (Claude Opus 5.5, effort low, server-side refusal fallback). Only on produce questions after a wrong answer, never reveals the answer, student input fenced as data, 40 hints/day per student (`Hint` table). Off unless `ANTHROPIC_API_KEY` is set.
- Content: `lib/content/linear-algebra/unit1.ts` (vectors → composition), `unit2.ts` (span → solving Ax = b), `unit3.ts` (eigenvectors → PCA). Vector items with `upToScale` accept any non-zero multiple (eigenvectors, directions). Widgets `eigen` (hunt for Av ∥ v) and `spread` (PCA projections).
- Statistics track: `lib/content/statistics/unit4.ts` (probability → Bayes, independence), `unit5.ts` (variance → covariance matrix, normal, MLE, least squares, losses as likelihoods). Stats widgets live in `components/widgets/StatsWidgets.tsx`: `sim`, `bayes`, `points1d`, `normal`, `likelihood`, `fitline`. Units carry a `track` label; `/learn` groups by it.
- Calculus track: `lib/content/calculus/unit6.ts` (derivative → backprop). Widgets in `components/widgets/CalcWidgets.tsx`: `tangent` (secant → tangent for x², (3x+1)², x³−3x), `gradient2d` (bowl x²+2y²), `descent` (L=(w−3)²+1; η>1 diverges).
- Neural networks track: `lib/content/networks/unit7.ts` (neuron → train a network). Widgets in `components/widgets/NNWidgets.tsx`: `neuron`, `playground` (real 2→H→1 net trained live with backprop; `tests/network.test.ts` checks it learns circle/XOR with tanh and can't without an activation).
- Batch 1 (more statistics + ML evaluation): `lib/content/statistics/describing.ts` (unit st-0: mean/median, quartiles & box plots, skew & charts, sampling methods, sampling bias), `distributions.ts` (st-3: binomial, Poisson, uniform/exponential, CLT, standard error), `inference.ts` (st-4: confidence intervals, hypothesis tests, errors & power, t-tests, chi-square, correlation vs causation/Simpson), `lib/content/ml/evaluation.ts` (ml-1, track "Machine learning": multiple regression & R², logistic regression, ridge/lasso, cross-validation, bias–variance, precision/recall/F1, ROC/AUC). Widgets in `components/widgets/InferenceWidgets.tsx`: `summary1d` (draggable box plot), `binomial`, `clt`, `cisim`, `pvalue`, `threshold` (confusion matrix + ROC). Course order in `lib/content/index.ts` puts every unit after the units its deps live in.
- Practice: `lib/content/generators.ts` (original compute generators) + `templates.ts` (question kinds: compute / reverse / interpret / error / real-world, levels 1–3) + `templates-batch1.ts` (batch-1 concepts) cover every concept (a test enforces it); `lib/learning/practice.ts` mixes target variants with prerequisites, steers towards held misconceptions, and `PRACTICE_STREAK` (3) in a row makes a concept solid. Generated ids are `gen~node~template~level~seed` (old 4-part ids rebuild as level 1).
- Teacher question editor: `/teacher/content` (teacher only). `CustomItem` rows hold editor input; `lib/content/customSchema.ts` validates and self-grades before save; `lib/content/custom.ts` serves them in practice (`cust~id~p`) and review (`cust~id~r`) via `resolveItem`. Archive instead of delete.
- Live: https://eigen-green.vercel.app (Vercel project `eigen`). `/api/health` checks the DB. Set Vercel env vars with `printf '%s' "$VAL" | vercel env add` — piping from PowerShell adds a newline and breaks them.

## Rules for content

- Every MC has exactly one correct option; every distractor is a real error and tagged with a `misconception` when diagnostic.
- Every misconception a check/predict can mark must be dislodgeable in the same lesson (a predict step for it, or another non-review item that targets it). `tests/content.test.ts` enforces this and that every stated answer grades correct.
- Math in `$...$` / `$$...$$`. Double the backslashes in TS strings.

## Run

- `npm run dev`, `npm test`, `npm run typecheck`, `npm run build`
- DB: Neon project `eigen` (`broad-band-27361521`). The app connects through `@prisma/adapter-neon` over WebSockets (443) because raw 5432 is blocked from this machine. `prisma db push` fails here for the same reason: apply schema changes with `npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script` (or `--from-url`) and run the SQL in Neon.
- `.env`: `DATABASE_URL`, `DIRECT_URL`, `INVITE_CODE`, `TEACHER_EMAIL`. The teacher email gets the TEACHER role at signup and sees `/teacher`.

- Text: `$...$` is maths. A literal dollar sign is `\$` in the rendered text, so `"\\$12"` in a TS string literal. `tests/latex.test.ts` fails on unbalanced `$`, prose swallowed into maths, KaTeX errors, or control characters from a lost backslash.
- Lesson intros: every lesson opens with a pinned scroll-driven 3D scene (`components/intro/`). `lib/content/intro.ts` maps each concept to an `IntroSpec` (plain data, from the lesson's own widget numbers, with overrides for concepts without one); `components/intro/programs.ts` turns a spec into particles/arrows/lines/readout as pure functions of scroll progress (tested in `tests/intro.test.ts`, including that readouts are true); `IntroScene.tsx` renders with three.js via `components/three/kit.ts` (shared with the landing film). Students returning to a LANDED/SOLID/MISCONCEPTION concept start at the lesson. Dev-only preview without an account: `/dev/intro/<nodeId>` (404 in production).
- Accounts: `/account` (progress by track, mix-ups, test history, name, password change: signs out other devices). Login locks for 15 minutes after 5 wrong passwords (`lib/auth/lockout.ts`, `User.failedLogins/lockedUntil`). A teacher can reset a student's password from `/teacher/students/<id>`: a temporary password is shown once, `mustChangePassword` makes `requireUser()` send them to `/account` until they change it.
- Teacher: `/teacher` is the class overview (assignments, class-wide live misconceptions, per-track progress per student); `/teacher/students/<id>` is one student's map, mix-ups, tests, recent answers; assignments (`Assignment` model) are created at `/teacher/assignments/new` and tracked at `/teacher/assignments/<id>`. Students see unfinished ones on `/learn`. Progress logic is pure in `lib/learning/summary.ts`. Every submitted test writes an `ExamRecord` (scope = unit id or "mock").
- Schema changes are SQL files in `prisma/sql/` applied with Neon (port 5432 is blocked here), then `npx prisma generate` with the dev server stopped (it locks the engine DLL on Windows).
- Local QA as another user: use http://127.0.0.1:3210 (separate cookie jar from localhost; allowed in `next.config.ts` `allowedDevOrigins`).

- Audience: competitive-exam students (JEE Main/Advanced, SAT and similar). Lessons are textbook sections: `components/textbook/Section.tsx` renders numbered Definition / Theorem (with Proof, ending ∎) / Example (★ level, solution on request) / Common errors / Formulas / Figures / Checks / Mastery check / Exercises n.m (Level I ≈ SAT/boards, II ≈ JEE Main, III ≈ JEE Advanced). Numbering (Part, Chapter, §) comes from `lib/content/numbering.ts`. The dashboard is the syllabus (`components/textbook/SyllabusView.tsx`); the dependency graph moved to `/learn/map`.
- Adding exam depth to a chapter: write `lib/content/<track>/unitN.depth.ts` (`Depth` per concept: definitions, theorems, examples, pitfalls, formulas, exercises built with `num/vec/mat/mc/ex` from `lib/content/deepen.ts`) and wrap the unit's nodes with `deepen(node, DEPTH[node.id])`. Exercise solutions never reach the browser before an attempt (`exerciseSolution` is attached to the grade). Tests check every exercise answer grades correct, every example has a multi-step solution, and all maths renders (tabs or newlines from a lost backslash fail the build). Probability answers use a tolerance helper (`fr`: exact fraction or 3 decimals). Chapters 1–6 are done; Chapters 7–11 (distributions, inference, calculus, networks, evaluation) are pending.
- Design rules: textbook look (serif `Source Serif 4` via next/font, paper/ink tokens, 3px corners, rules not shadows), no emoji, no gradient text. Dev-only previews without an account: `/dev/lesson/<nodeId>`, `/dev/syllabus` (404 in production).
